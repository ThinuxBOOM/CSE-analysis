# F6.2: Economic identity, source observations, validation and reconciliation

**Status: FINAL DESIGN.** This is documentation only: no schema, no migration and no implementation.

**Date:** 2026-09-27.

**Baseline**
- F5 is frozen at `b9c2688`.
- F6.1 is committed at `68705bc` (`f6.validation.1`).
- The architecture assessment was accepted: a Linux home server with local PostgreSQL as the authoritative database, GitHub for source control only, and a server that may be offline for hours or days.

**Supersedes** the earlier F6.2 design report wherever they differ. §16 lists what changed.

**Evidence**
- The 26-filing F6 corpus (derived data only; no documents are retained), re-measured under the final decisions with the committed F6.1 code. Results are in §14.
- The corpus was never issuer-linked, so the source symbol stands in for `issuer_id` in every measurement.

Decision numbers `#1`–`#41` refer to the owner's final F6.2 decisions (2026-09-27). Rules marked `D-n` are derived by applying those decisions (§15.2). Rules marked `R-n` are still open (§15.3).

## 0. Scope and boundaries

- **F6 is pure.** It does not depend on the database engine, operating system, scheduler, network or deployment. Identity, admission, observation-building and reconciliation are deterministic functions of their inputs and versions: same inputs and versions give byte-identical output.
- **What this document specifies.** The persistent models below say what is recorded, how it is keyed and what must hold. Physical DDL belongs to F6.4 (and to the F4 persistence phase), not to this document.
- **Where availability belongs.** Availability and as-of are data provenance, so they are specified here (§9). How and when jobs run is out of scope. F6 never infers a source's publication time from when a local job happened to run.
- **F6.1 is unchanged.** Every rule stricter than F6.1 lives in a separate, versioned admission layer (§3).
- **PDFs stay temporary.** F6 never needs the document; it works only from persisted F3, F4 and F5 data.

## 1. Six concepts F6 keeps apart

| Concept | What it is | Key | Mutability | Produced by |
|---|---|---|---|---|
| **Validation result** | F6.1's verdict and the admission decision for ONE F5 candidate, under one version set and one input set | (candidate, validation run) | Immutable, append-only | F6.1 primitives plus the admission layer |
| **Source observation (SO)** | One F5 run's admitted evidence for one economic-fact identity | (validation run, ef_key) | Immutable **table** rows | SO builder |
| **Economic fact (EF)** | The identity of the thing measured: issuer, concept, period, scope, operations, maturity, currency | ef_key | Immutable identity row; **carries no value** | Identity builder |
| **Reconciliation result** | The state and value F6 concludes for one EF from one specific SO set | (ef_key, configuration, input_hash) | Append-only history | Reconciliation function |
| **Source availability** | When the *source* (CSE) made the information available | Raw evidence on the filing and run; the chosen value comes from an F8 policy | Raw evidence immutable; policy versioned | F1 / F5 snapshot; F8 |
| **System knowledge time** | When *our system* held the evidence or conclusion | `recorded_at` of the F5 run, validation run, SO and reconciliation record | Immutable | The pipeline |

A fact's identity row never stores a value. Values exist only in reconciliation results, and every reconciliation result lists the exact SOs it was computed from. So a fact can never erase the observations that support it or conflict with it.

## 2. Final economic fact identity (`f6.identity.1`)

`ef_key` is the SHA-256 of the canonical JSON of the following fields, in this order:

| # | Field | Values | Rule |
|---|---|---|---|
| 1 | `identity_version` | `f6.identity.1` | Any rule change means a new version. Existing identities are never rewritten |
| 2 | `issuer_id` | F5 `issuers.issuer_id` | Only through an admissible issuer link (§3 A-2; #24–#26) |
| 3 | `concept_key` | v1 vocabulary | Also carries attribution (owners / NCI / not applicable) and value type (#36) |
| 4 | `period_kind` | `instant`, `duration` | |
| 5 | `period_end` | exact date | Month-end is not required (e.g. UCAR's 25th) |
| 6 | `duration_months` | positive integer for durations; null for instants | A valid duration is required (#14, #15) |
| 7 | `scope` | `group`, `company`, `bank`, `unlabelled` | The reported scope. F5 `unstated` becomes `unlabelled` (#1, #2) |
| 8 | `operations` | `total_or_unstated`, `continuing`, `discontinued` | Only trusted values (§3 A-3; #21–#23) |
| 9 | `maturity` | `current`, `non_current` for `interest_bearing_borrowings`; `not_applicable` for every other concept | A borrowing with undetermined maturity is not admitted (D-2) |
| 10 | `currency` | 3-letter code as reported (F6.1 requires `^[A-Z]{3}$`) | Never defaulted or converted (#3–#9) |

**Not in the identity:**
- role (#35);
- period start (#16, #38);
- audit status (#37);
- fiscal label, reported scale, printed representation;
- F5 canonical scope, F3 document type, filing, run;
- any F3, F4, F5 or F6.1 version.

These are all attributes of the SO (§5).

## 3. Admission: from validation result to observation (`f6.admission.1`)

F6.1 (`f6.validation.1`) runs unchanged on every F5 candidate. Admission is a separate, versioned, pure step. It reads the F6.1 result and three other inputs: the issuer-link decision, the operations-partition rule, and the scope/maturity mapping. It decides whether the candidate becomes an SO member.

The admission rules, applied to every candidate:

- **A-1 Value.**
  - Admitted as a **numeric observation**: F6.1 `eligible`.
  - Admitted as a **nil observation**: F6.1 `normalization_required`, whose *only* normalisation reason is `value_reported_nil` (a printed dash) or `value_reported_nil_word` (`Nil` / `None`), and with no ineligibility reason.
  - Everything else is not admitted. Its F6.1 reasons are kept. This covers `ineligible`, blank, N/A, non-numeric, and scale or currency problems.
- **A-2 Issuer** (#24–#26).
  - The filing's issuer-link decision (D-1) must have `status = 'evidenced'` **and** `basis` in (`listing_symbol_sec_id`, `both`).
  - `basis = 'document_path_prefix'` alone is not admitted (reason `issuer_link_path_prefix_only`).
  - F5's rules decide the link. F6 only refuses to rely on path-prefix-only links.
- **A-3 Operations** (#21–#23).
  - Basis `row_label` or `none`: F6.1's result stands.
  - Basis `section_label`, on **any** row (total or not): admitted only when rule **OP1** below returns `pass` for that row's group. Otherwise the reason is `operations_section_derived_unvalidated:<outcome>`.
  - An OP1 `pass` lifts exactly one F6.1 reason, `operations_section_derived_on_total_row`, and nothing else.
- **A-4 Maturity (D-2).** An `interest_bearing_borrowings` candidate needs F6.1 maturity `current` or `non_current`. Otherwise the reason is `maturity_undetermined:<basis>`.
- **A-5 Scope.** Identity scope is F5 `reported_scope` when it is `group`, `company` or `bank`, and `unlabelled` when it is `unstated`. Group/Company/Bank are never inferred from a missing label (#1).
- **A-6 Identity completeness.** Every identity field must be present. Otherwise the candidate is not admitted.

### OP1: controlled operations-partition rule (`f6.op1.partition.1`)

This is the controlled arithmetic-validation rule referred to in #22 and #23.

- **Group.**
  - One statement column: F6.1's `arithmetic_group_key` (statement root, kind, period kind, period end, duration, reported scope, role).
  - One `concept_key`.
  - Only F5 `proposed` candidates with a column-derived period.
- **Terms.** Take the values for `continuing`, `discontinued` and `total_or_unstated`. For each of the three:
  - at least one row must exist;
  - every value must be F6.1 `numeric` and normalised;
  - there must be exactly one distinct normalised value.

  All three terms must share one currency and value type.
- **Test.** `|continuing + discontinued − total| ≤ half_unit(c) + half_unit(d) + half_unit(t)` (inclusive, exact Decimal).
- **Outcomes:**
  - `pass`: validates the section-derived operations of the `continuing` and `discontinued` rows **in that group only**;
  - `fail`;
  - `insufficient_evidence`: a term is missing, a term is nil or non-numeric, a term has several values, or currencies differ.
- **What it never does:**
  - relabel a row (for example, turn a "discontinued" row into a total);
  - treat nil as zero (D-3);
  - borrow evidence from another column, concept or document.
- **Recorded.** One OP1 record per group, with its terms (source keys, values, half-units), the tolerance, the difference and the outcome.
- **Corpus (LOLC 52684, all 20 section-derived candidates):**
  - 6 `pass`: comparative columns, where owners and NCI continuing + discontinued equal the total exactly.
  - 14 `insufficient_evidence`:
    - 10 because the current-period discontinued value is printed `-`;
    - 4 because the row "Profit/(loss) for the period" has no separate total row to test against. That row is actually the total, but its section labels it discontinued.

  So the mislabelled total is never admitted as discontinued.

## 4. Validation-result model (persistent, versioned)

Every F5 candidate gets a validation record in every validation run, whatever its status: proposed, ambiguous, conflicting or unresolved, and admitted or not.

**`validation_run`**: one per F5 run × version set × input set.
- References: `f5_run_id`, `cse_filing_id`, `document_sha256`.
- Versions: `validation_version` (`f6.validation.1`), `admission_version` (`f6.admission.1`), `op1_version`, `input_policy_version` (`f6.inputs.1`).
- Inputs used:
  - the issuer-link decision (`filing_issuer_links.id`, with its status and basis);
  - the publication date and the field it came from (D-7);
  - the F3 classification id, with its FYE basis/status and period status.
- Hashes: `input_hash` over the run's inputs and `output_hash` over its outputs.
- Times and references: `started_at`, `finished_at`, `recorded_at`, `code_revision`, and an optional opaque `job_attempt_ref`. F6 logic never reads `job_attempt_ref`.

**`candidate_validation`**: one per candidate per validation run.
- `candidate_id` and `input_hash` (SHA-256 of the canonical JSON of the `CandidateContext` plus `RunEvidence`).
- F6.1 output:
  - eligibility, `ineligible_reasons`, `normalization_reasons`;
  - period result: status, kind, start, end, duration, class, fiscal label passed through, reasons, notes;
  - value result: state, dash glyphs, `normalized_value`, `printed_unit`, `half_unit`, currency, `scale_applied`, rule, status, reasons;
  - operations result: operations, basis, trust, reason;
  - maturity result.
- Admission output:
  - `admitted` (boolean);
  - `value_kind` (`numeric` or `nil`) and `nil_form` (dash glyph names or the word);
  - admission reasons;
  - `ef_key` when admitted;
  - a reference to the OP1 record, if one applied.
- `output_hash`.

**Run diagnostics**, per validation run: A1–A5 arithmetic results with their exact terms; sign results (convention, basis and contribution value, as *interpretation* only); statement sign conventions; OP1 records.

**Rules:**
- **Reproducible.** Re-running F6.1 and admission on the same inputs and versions gives the same `output_hash`.
- **Immutable.** A stored record is never updated. A new version, or any changed input (for example a new issuer-link decision), creates a new validation run. Old runs stay.
- **Reported evidence is never mutated** (#39–#41). The raw value, parsed value, representation, printed sign, reported scale and currency stay exactly as F5 persisted them. `normalized_value` and `half_unit` are an *additional* representation stored next to them.
- **Reasons are stable codes,** such as F6.1's `role_untrusted`, `duration_months_missing` and `period_end_after_publication`, or admission codes such as `issuer_link_path_prefix_only`.

## 5. Source-observation model: a permanent TABLE

Source observations are a **PostgreSQL table, not a view.**

- **Key:** `(validation_run_id, ef_key)` is unique. There is one SO per F5 run (via its validation run) per identity. An SO never spans runs or documents.

| Group | Fields |
|---|---|
| Identity | `so_id`, `ef_key` (FK to the fact), `validation_run_id`, `f5_run_id`, `cse_filing_id`, `document_sha256`, the identity, validation, admission and OP1 versions |
| Members | Table `so_member`: `candidate_id`, `candidate_validation_id`, `statement_index`, `row_index`, `column_index`, `value_ordinal` (these index the retained F4 cell), `value_kind` |
| Reported value (copied verbatim from the representative member; F5 stays the source of truth, and the copies must equal it) | `raw_value`, `parsed_value`, `representation_class`, `printed_decimals`, `sign_as_printed`, `reported_scale`, `scale_basis`, `currency`, `value_type` |
| Normalised representation | `value_kind` (`numeric` or `nil`), `nil_form`, `normalized_value`, `half_unit`, `interval_low` and `interval_high` (intersection across members), `representative_member` |
| Status | `observation_status`: `consistent`, or `internally_conflicting` (members disagree numerically, or nil and numeric are mixed). An internally conflicting SO has no representative and no interval |
| Period | kind, end, duration (identity), printed start (attribute), fiscal label (passed through only when documented) |
| Scope | Identity scope; F5 `reported_scope` and its basis; F5 `canonical_scope` and its basis (attributes) |
| Operations and maturity | Operations with basis and admission route (`row_label`, `none`, or `section_label+OP1`); maturity with basis |
| Role and attribution | Member roles (`current` / `comparative`; recorded as a set, annotated if more than one); attribution from the concept |
| Audit and restatement | Per member column: `audit_label_reported`, `audit_evidence_source`, `audit_trust`, `restated` (attributes only; #37) |
| Document context | F3 `document_type`, `underlying_type` and their statuses (attributes only; never gates, D-9) |
| Provenance | Via members: page and bounding box of each cell, plus the F4 extraction and F5 run keys |
| Times | `evidence_recorded_at` (F5 run `recorded_at`), `recorded_at` (when the SO was inserted). Source-availability evidence is reached through the run (§9) |
| Reconciliation membership | Table `reconciliation_input` (`reconciliation_record_id`, `so_id`, `role_in_outcome`) |

SOs are immutable. A new validation run creates new SOs; earlier SOs remain.

## 6. Economic-fact model

- **Table:** one row per `ef_key`, holding the identity fields as columns, `identity_version` and `first_recorded_at`. It is inserted if absent, and never updated or deleted. It has **no value columns.**
- **LKR-analysis eligibility is derived, not stored as state:** a fact is eligible when `currency = 'LKR'` (§8.2).
- A fact exists once any admitted SO has its identity. Its state and value are only in reconciliation results (§7).

## 7. Reconciliation model (`f6.reconciliation.1`)

**Inputs.** One EF, plus the SOs selected by an explicit, versioned **reconciliation configuration**:
- **F6 versions:** exactly one identity, validation, admission and OP1 version.
- **One F5 run per document** (by document SHA-256): the most recently recorded run whose F3, F4 and F5 versions are in the configuration's accepted set. This chooses between *our own processing runs of the same document*. It never chooses between documents (D-6).
- **Duplicate filings:** filings that share a document SHA-256 count as **one document**, annotated `same_document_multiple_filings`.
- **As-of cut:** optional (§9).

**States.** There are three, plus `value_kind` (`numeric` or `nil`) whenever the state is not conflicting:

| State | Condition |
|---|---|
| `single_source` | SOs from exactly one document, observation consistent |
| `corroborated` | Two or more distinct documents, every SO consistent, and every pair agrees. Numeric: the V8 test `|a−b| ≤ h_a + h_b`, same currency and value type. Nil: all nil |
| `conflicting` | Any SO internally conflicting, any pair disagreeing, or nil against numeric (a printed `0` counts as numeric) |

**Value** (#27–#30):
- **Interval:** `[max(vᵢ − hᵢ), min(vᵢ + hᵢ)]` over all SOs. Because every pair agrees, the interval is never empty (one-dimensional Helly).
- **Representative:** the SO with the smallest half-unit, with its reported value exactly as printed (raw, parsed, scale) and its normalised value.
  - If several SOs share the smallest half-unit and have the **same** value, that value is the representative.
  - If they **differ**, there is no representative: interval only, annotated `representative_ambiguous` (D-4).
  - The representative is never adjusted into the interval.
- **Single source:** the SO's own interval and representative.
- **Nil:** value `nil`; no interval, no normalised value, never 0.
- **Conflicting:** no value, no interval and no representative. Every SO is listed with its value.

**Record** (`reconciliation_record`, append-only):
- `ef_key`, `reconciliation_version`, `configuration_id`;
- `input_hash` (ordered SO ids, their output hashes, and the configuration);
- state, `value_kind`, interval, `representative_so_id` with a verbatim copy of its value, `document_count`, `so_count`;
- annotations and reasons;
- `recorded_at`, a per-EF `sequence`, and `previous_record_id`.

Membership is recorded in `reconciliation_input`, marking each SO as `supporting`, `conflicting` or `representative`.

A new record is appended only when `input_hash` differs from the latest record for that EF under that configuration. The "current" state is the latest record by sequence (a view). Nothing is overwritten or deleted.

**Annotations** (they never change the state):
- `agreement_within_precision_only`
- `differs_across_document_versions` (an errata, amendment or reissue is involved in the disagreement)
- `differs_interim_vs_annual`
- `restated_comparative_present`
- `nil_vs_numeric`
- `internal_conflict`
- `sign_only_difference`
- `multi_currency_presentation`
- `representative_ambiguous`
- `same_document_multiple_filings`
- `audit_labels_differ`

**No precedence of any kind chooses a value:** not latest, audited, annual, errata, amendment, restated, or a different document type. Precision only chooses a *representative* among values that already agree.

## 8. Policies

### 8.1 Nil (#10, #11)
- **Nil observations:** a printed dash (`reported_nil`, with glyph names kept) or the words `Nil` / `None` (`reported_nil_word`). Both are admitted as distinct observations (§3 A-1).
- **Not observations:** `N/A`, blank, text and percentages. The candidate and its validation result are still kept.
- **Nil is never 0:** not in storage, not in comparison, not in A1–A5, not in OP1 (D-3). A printed `0` is numeric zero and stays distinct from nil.
- **In an SO:** all members nil gives a nil SO. Nil mixed with numeric gives `internally_conflicting`.
- **In a fact:**
  - all SOs nil gives `single_source` or `corroborated` with `value_kind = nil`;
  - nil against numeric gives `conflicting` with `nil_vs_numeric`.
- **Corpus:** 43 nil candidates admitted, 41 nil SOs, 27 single-source and 7 corroborated nil facts, and 0 nil-versus-numeric conflicts.

### 8.2 Currency (#3–#9)
- **Currency is part of the identity.** The evidence is F4's statement currency, taken from printed header or footer phrases: `Rs` / `LKR` / `rupee` become LKR; `US$` / `USD` become USD.
- **Missing or unrecognised currency means not admitted** (`currency_not_reported` / `currency_unrecognised`). Currency is never inferred from the listing, the trading currency, the issuer's country or another statement (#6).
- **No FX conversion in F6** (#5, #9). Any future conversion is a separate, versioned transformation layer.
- **Non-LKR facts** are kept as economic facts under their own currency. They are **not eligible for LKR analysis** and never become LKR facts (#7, #8; D-8).
- **`multi_currency_presentation`** is annotated on both sides when one document presents the same identity (except currency) in two currencies.
- **Corpus:** 1,424 LKR facts and 64 USD facts. All 64 USD facts are convenience statements printed next to LKR statements in the same document (COMB annual report: 60; TESS: 4).
- Whether an LKR presentation can itself be a convenience translation is R-1.

### 8.3 Scope (#1, #2, #12, #13)
- **Identity scope** is `group`, `company`, `bank` or `unlabelled` (reported). They are never merged with each other, and an unlabelled scope is never merged with a labelled one.
- **F5 canonical scope** (`consolidated` / `separate` / `unresolved`) is an SO attribute only.
- **Supplementary or untrusted tables** (F6.1 `role_untrusted`) are excluded from facts. They stay in F4 and F5 for audit and reprocessing.
- **Corpus facts by scope:** group 666, company 433, bank 169, unlabelled 220.
- **Known consequence:** if an issuer switches from unlabelled to labelled statements, its facts fragment rather than being falsely merged.

### 8.4 Duration and period (#14–#20, #38)
- **Instant:** kind plus end date.
- **Duration:** kind, end date and `duration_months`. 3M, 6M, 9M, 12M and other N-month durations are each their own facts. A missing or invalid duration is not admitted (111 candidates in the corpus).
- **Period start** is an attribute. F6.1 checks it against the end date and duration.
- **Never derived:** a Q4 from FY − 9M; a quarter from 12M data; anything from titles, `manualDate` or an inferred FYE. Fiscal labels are passed through only from a documented, trusted F3 FYE, and only as an attribute.
- **Instant from a duration column's end** (`cash_at_end_of_period`): an instant at that end date, with its derivation recorded.
- **12M interim and audited annual** reports are separate SOs of one identity (#20). A disagreement is `conflicting` with `differs_interim_vs_annual`.

### 8.5 Operations (#21–#23)
- **Row-label operations** are trusted, as are rows that make no operations claim (`none`).
- **Section-derived operations** are trusted only through OP1 `pass` (§3), on total and non-total rows alike.
- Operations are never relabelled.

### 8.6 Conflict and corroboration (#27–#34)
- Everything is kept. There is no winner.
- **Supersession, errata, amendment and restatement** are annotated only. F8 decides how sources relate.
- **Corroboration** counts only distinct documents (by SHA-256), within one configuration.

### 8.7 Sign (#39–#41; D-5)
- Values are compared exactly as reported and normalised, with their printed signs.
- F6.1's sign conventions and contribution values are recorded as interpretation. They are **never used to make two values agree**. Values that differ only in sign are `conflicting` with `sign_only_difference`.
- **Corpus:** 18 multi-document expense facts, all with the same printed sign.

### 8.8 Audit, restatement, amendment (#33, #34, #37)
- Audit label (with source and trust), the restated flag and the F3 document and underlying type are **SO attributes**. They never gate admission and never set precedence.
- A F3 document type of `undetermined` (for example COMB's 12M interim) does not block anything (D-9).

## 9. Provenance and as-of model

### 9.1 Times that must never be conflated

| Time | Meaning | Recorded in (existing or planned) |
|---|---|---|
| **Source availability evidence** | When CSE made the source available | `report_filings.uploaded_at` / `authorized_at`, with their raw strings (F1); the F5 run snapshot: `uploaded_at`, `authorized_at`, `path_epoch_at`, `cdn_last_modified` |
| **Source availability (chosen)** | The single value used for backtests | An F8 versioned policy over the evidence above (deferred since F5.0) |
| **First seen by our system** | When F1 first saw the listing, and when each metadata version was seen | `report_filings.first_seen_at`; `report_filing_observations.observed_at`; F5 snapshot `f1_first_seen_at` |
| **Retrieval** | When F2 fetched the document | F5 run `document_retrieved_at` |
| **Processing / knowledge** | When results became durable | F3 `classified_at`; `filing_issuer_links.decided_at`; F5 run `recorded_at`; F6 `validation_run.recorded_at`; SO `recorded_at`; `reconciliation_record.recorded_at` |
| **Scheduled time and actual execution** | When a job was due, and when it actually ran | The job/attempt layer (infrastructure, planned). F6 processing runs carry only an opaque, nullable reference plus their own `started_at` / `finished_at`, and F6 logic never reads them |
| **Analysis / prediction cutoff** | The information cutoff of a consumer run | The consumer's run record (planned): `cutoff_at`, knowledge mode, availability-policy version, F6 configuration |

**Invariants:**
- `first_seen_at`, retrieval, processing, scheduled and execution times are **never** used as, or to infer, source publication or availability time.
- Downtime shifts system times later. It never changes source-availability evidence.

### 9.2 As-of questions

1. **What did the system actually conclude at T?** (as recorded) For each EF, take the latest reconciliation record with `recorded_at ≤ T`.
2. **What could the system have concluded at T with logic V?** (recomputed) Select:
   - F5 runs with `recorded_at ≤ T`;
   - the issuer-link decision and F3 classification with `decided_at` / `classified_at ≤ T`;
   - the publication-date input as known at T.

   Then apply versions V as pure functions. The result is deterministic, and version sets are fixed for backtests.
3. **What had the source made available by T?** (retrospective) SOs whose source availability under policy P is `≤ T`, regardless of when our system learned of them. Results must be labelled retrospective. **Never** use this for a live analysis or prediction, or to claim the system knew something.

Live analyses and predictions use (1) or (2) with T equal to their cutoff. Because the server can be offline, the system-knowledge view (1, 2) can lag the source view (3) by days. Both are always reconstructible.

## 10. F4 → F5 → F6 persistence flow

```
F1  report_filings / observations / discovery runs ..................... persisted (0004)
F2  temporary document (validated, SHA-256) ............................ never persisted; deleted + deletion verified
    └─ inside the F2 consumer, in memory only:
       F3 classify  -> classification, statement periods, evidence
       F4 extract   -> statements, columns, rows, cells (+ page trust, signals, cross-check, companion check)
       F5 build     -> mapped rows + candidates of every status
F2  delete + verify
Persist (only if the consumer succeeded and the deletion was verified; one transaction per filing):
       F3 classification (0005) -> filing->issuer decision (0007)
       -> F4 extraction, FULL structure (planned layer)
       -> F5 run / statements / columns / rows / candidates (0008) + candidate->F4-cell link
F6  from the database only (no PDF):
       validation_run (F6.1 + admission + OP1) -> candidate_validation (ALL candidates) + diagnostics
       -> source_observation + so_member (TABLE) -> economic_fact (insert-if-absent)
       -> reconciliation_record + reconciliation_input (append when the input hash changes)
```

### F4 layer: requirements for its later implementation phase

- **Keyed by** `(cse_filing_id, document_sha256, word_extractor, f4_extractor_version, classification_id)`: the same components the F5 run key uses.
- **Stored:**
  - document status, reasons, page count, compact page trust, companion-check summary;
  - statements: index, kind, pages, continuation, scope, heading (at most 160 characters), heading page and bounding box, status, reasons, scale, scale status, scale basis, scale evidence, currency, signals, cross-check summary;
  - **all** columns: kind, status, extents, header (at most 160 characters), period fields and basis, role and basis, scope and basis, audit status, restated flag, reasons;
  - **all** rows: index, page, raw and normalised label, extents, line count, wrapped flag, section label, note reference, kind, status, reasons;
  - **all** cells: raw value, parsed value, representation class, scale and basis, currency, coordinates, extractor and version, status, reasons, cross-check, confidence, quality flags.
- **Cell key:** `(statement_index, row_index, column_index, value_ordinal)`, where the ordinal is F5's reading-order ordinal among cells with the same row and column. F5 candidates therefore link to their F4 cell deterministically.
- **Not stored:** PDF bytes, document or page text, the word/line/phrase layer, page images, temporary paths.
- **Lossless for F5:** re-running the F5 builder from the persisted F3 and F4 must reproduce F5's `content_sha256` exactly. This is the acceptance test for that phase. A new F5 mapper or vocabulary then needs no download. A new **F4 extractor** version still needs the PDF.
- **F5 is unchanged by this layer.** It still persists the mapped subset plus every candidate. Cells F5 skipped (unresolved period or kind mismatch) are preserved in the F4 layer.

**F6.1 inputs from the database.** Every `CandidateContext` field exists in the persisted F5 tables (0008). The statement root comes from `financial_statement_extracts.continuation_of`.

## 11. Storage and retention policy

> **Principle:** preserve expensive-to-reconstruct structured evidence; discard only information whose retention would create disproportionate complexity or privacy/security risk. Storage size is not a reason to discard structured evidence.

**KEEP permanently** (append-only; superseded versions are never pruned, and recomputation never deletes):
- F1 listing metadata and its history;
- F3 classification and evidence;
- the **full** F4 structure;
- **all** F5 candidates, whatever their status or acceptance;
- **all** F6 validation results and diagnostics;
- source observations (a **table**);
- economic-fact identities;
- reconciliation history;
- issuer evidence and decisions;
- raw market observations;
- ingestion, run and audit metadata;
- later, AI analysis and prediction history.

**DO NOT KEEP:**
- PDF binaries (in PostgreSQL or anywhere);
- full document text or page images (unless a later explicit feature requires them);
- secrets;
- temporary file paths.

**PDFs remain temporary extraction inputs.**

## 13. Invariants F6.3 (pure) and F6.4 (storage) must enforce

1. F6.1 is unchanged. Admission is a separate, versioned layer.
2. The identity contains exactly the §2 fields. Role, audit status, period start, scale, document type, filing, run and processing versions never enter it.
3. No fact exists without an evidenced, non-path-prefix-only issuer link.
4. An SO belongs to exactly one F5 run and one validation run. A 12M interim and an annual report are always separate SOs.
5. Agreement is always F6.1 `compare_values` (V8, inclusive), tested pairwise over every SO. Nil agrees only with nil.
6. A conflicting result carries every SO and no value. Nothing is selected.
7. There is no precedence by latest, audited, annual, errata, amendment, restated or document type.
8. Corroboration counts distinct document SHA-256s within one explicit configuration. Two runs of one document never count twice.
9. Every record is append-only and versioned. Nothing is updated or deleted. "Current" is always a view.
10. Reported values are never mutated. Arithmetic is exact Decimal. There is no FX conversion and no scaling of per-share values.
11. Nil is never zero, in any rule.
12. No period is derived: no Q4 subtraction, no quarter from 12M, no titles, no `manualDate`, no inferred FYE.
13. `group`, `company`, `bank` and `unlabelled` never merge; currencies never merge; maturities never merge; operations are never relabelled.
14. Untrusted roles, unvalidated section-derived operations, undetermined borrowing maturity, missing durations and missing currencies are never admitted.
15. Output is deterministic: identical inputs and versions give byte-identical records and hashes, whatever the input order.
16. No source-availability time is inferred from first-seen, retrieval, processing, scheduled or execution times.
17. Any as-of result can be recomputed from persisted evidence (§9.2).
18. F6 never reads a PDF, a document's text, the clock (outside recorded timestamps), the network, or scheduler state.

### 15.2 Rules derived from those decisions (not new choices)

- **D-1. Which issuer link is used.**
  - Validation uses the latest `filing_issuer_links` decision for the filing at validation time, recorded by id.
  - The F5 run snapshot is provenance only.
  - A new decision means a new validation run.
- **D-2. Borrowing maturity.** A borrowing whose maturity can't be established is not admitted. This applies #15's rule (an identity field that applies to the concept must be valid) to maturity. Corpus: DIMO, 6.
- **D-3. Nil in arithmetic.** Nil is never treated as zero in A1–A5 or OP1; a nil term makes the check `insufficient_evidence` (from #10).
- **D-4. Representative ties.** If the finest-precision SOs have different values, there is no representative; the interval stands alone (#28, #29). Corpus: 0.
- **D-5. Signs in comparison.** Comparisons use the reported sign. Sign interpretation never creates agreement. Differences only in sign are conflicting with `sign_only_difference` (#39, #40). Corpus: 0.
- **D-6. Independent documents.**
  - Corroboration counts distinct document SHA-256s.
  - One F5 run is used per document, chosen by an explicit, versioned configuration.
  - This is not "latest document wins": it chooses among our own processing runs of one document.
- **D-7. Publication date for F6.1's check.**
  - The date used for `period_end_after_publication` is the Asia/Colombo date of `report_filings.uploaded_at` (input policy `f6.inputs.1`).
  - It is never first-seen, retrieval or processing time. If it is missing, the candidate is ineligible.
  - This is a sanity input, not the F8 availability policy.
- **D-8. Non-LKR facts.** They are kept as their own facts, never converted, and flagged as not eligible for LKR analysis (#3–#9).
- **D-9. Document type never gates admission.** F3 document type, including `undetermined`, is an attribute (#20, #33, #37).

### 15.3 Remaining owner decisions

- **R-1 (does not block F6.3). A document that presents the same statements in LKR and another currency, where the LKR set might itself be a convenience translation of a non-LKR reporting currency.** F6 cannot tell this from the printed currency.
  - Default in this design: printed LKR is eligible for LKR analysis, and both sides are annotated `multi_currency_presentation`.
  - Corpus: no such case. All 64 USD facts are USD convenience statements next to LKR primary statements.
  - The decision: whether evidence such as a "convenience translation" heading must make the LKR side ineligible, and whether that belongs in F6 or the later FX/presentation layer.

## 16. Changes from the earlier F6.2 report

- **§11 storage is rewritten.** Validation results are persisted (previously "recompute, don't store"). SOs are a table (previously "optionally a view"). The full F4 structure is retained. There are no free-tier constraints.
- **The open decisions are closed** by the owner's decisions (§15.1).
- **Nil facts** now use `single_source` / `corroborated` with `value_kind = nil`, instead of a separate `nil_reported` state.
- **Section-derived operations** are admitted only through OP1, including on non-total rows (F6.1 trusts those; admission is stricter).
- **Issuer path-prefix-only links** are excluded.
- **Cross-document sign comparison** is conservative (D-5), replacing the earlier "hybrid" proposal.
- **Added:** the full availability/as-of model (§9), the F4 → F5 → F6 persistence flow (§10), and the validation-result and reconciliation-record models (§4, §7).
- **Sizing is informative only** (§12).
